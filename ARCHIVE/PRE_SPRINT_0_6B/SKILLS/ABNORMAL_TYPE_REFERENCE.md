Esta referencia lista los valores verificados del enum para indexación y búsqueda; la clasificación por skill debe verificarse contra `dist/game/data/stats/skills/*.xml`.

## 1. Semántica del sistema

`AbnormalType` es la clave de agrupación para el **stacking/reemplazo** de efectos continuos:

- `EffectList._stackedEffects: Map<AbnormalType, BuffInfo>` (`EffectList.java` L1479)
- Dos skills con el **mismo** `AbnormalType` compiten: gana la de mayor/igual `abnormalLevel`.
- Si `abnormalType == NONE`, el reemplazo se hace por **skill ID** en lugar de por tipo.

### Regla de reemplazo verificada
```
skill.getAbnormalType() == oldSkill.getAbnormalType()
&& skill.getAbnormalLevel() >= oldSkill.getAbnormalLevel()
    → old removed / hidden

skill.getAbnormalType() == oldSkill.getAbnormalType()
&& skill.getAbnormalLevel() < oldSkill.getAbnormalLevel()
    → new skill ignored
```

### Cross-AbnormalType
> **SOURCE_REQUIRED**: no existe en SOURCE una regla general que diga que `AbnormalType.A` y `AbnormalType.B` (distintos) sean mutuamente excluyentes. Cada caso debe verificarse en el XML de la skill.

## 3. Notas de uso

- El valor `NONE` (número 197) indica que la skill no participa en el stacking por `AbnormalType`; se reemplaza por skill ID.
- Los valores `DANCE_OF_*` y `SONG_OF_*` se usan para las dances/songs (agrupadas en `_dances`).
- Los valores `ULTIMATE_BUFF` y `ULTIMATE_DEBUFF` sugieren skills especiales, pero su tratamiento exacto depende del XML.
- `HP_RECOVER` identifica healing potion skills (`Skill.isHealingPotionSkill()`).
